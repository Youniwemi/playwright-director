## Definition of done

A feature or behavior change is **not done** until all of these ship together (same PR):

1. **`CLAUDE.md`** updated — architecture, options, design decisions
2. **The skill** in `skills/tutorialize/` updated — especially `references/api.md` for API or timing changes
3. **`README.md`** updated — every user-facing option and workflow; site-visible changes get screenshots in `docs/images/` (~900px wide, referenced with relative paths like `docs/images/x.png` — GitHub renders them on any branch, and npm resolves them through package.json's `repository` field)
4. **Unit tests** covering the new behavior (`npm test` green)
5. **`npm run build`** run, so the committed `dist/` matches `src/`
6. **The project site** (`landing/index.html`) updated when the change is meaningful to users — a new feature, capability, or workflow deserves a feature card, section, or hero mention (with a live demo where the deployed gallery makes one possible). Internal refactors, fixes, and minor option tweaks don't.

Before declaring any task complete, walk this list and fix what's missing.

## What this is

`playwright-director` is a standalone npm package that turns Playwright E2E tests into directed video guides. Tests run normally in CI; with `TUTORIAL_MODE=true` they produce videos with TTS voice, animated cursor, step overlays, and ffmpeg post-processing.

## Commands

```bash
npm run build      # tsc + copy styles.css → dist/
npm test           # vitest run (unit tests)

# E2E tests (requires Playwright browsers)
npx playwright test                          # all e2e tests (non-tutorial mode)
TUTORIAL_MODE=true TUTORIAL_VOICE=false \
  npx playwright test e2e/overlay-position   # single e2e file with overlays
```

## Architecture

The package has a **dual-mode design**: all tutorial logic (overlays, cursor, voice, music) is no-op when `TUTORIAL_MODE !== 'true'`. In non-tutorial mode, `complete()` simply executes queued step actions sequentially.

### Core class: `Tutorial` (`src/Tutorial.ts`)

Orchestrates seven subsystems, each in its own file:

| Subsystem | File | Responsibility |
|---|---|---|
| `TutorialVoice` | `src/voice.ts` | TTS audio generation (macOS `say` / Edge TTS / custom cmd), caching via content hash, in-browser playback |
| `TutorialMusic` | `src/music.ts` | In-browser background music (live preview only — actual audio is mixed by ffmpeg) |
| `TutorialCursor` | `src/cursor.ts` | Animated SVG cursor injected into the page, smooth eased movement |
| `TutorialOverlay` | `src/overlay.ts` + `overlay-html.ts` | Step banners, context cards, completion screen, email preview — all rendered as injected HTML |
| `TutorialZoom` | `src/zoom.ts` | Camera zoom on an element (`zoom()` / `zoomIn()` / `zoomOut()`), optional blur of the rest |
| `TutorialFastForward` | `src/fast-forward.ts` | Fast-forwarded spans: in-page VHS OSD + pure time-mapping/ffmpeg filter helpers |
| `TutorialTimeline` | `src/timeline.ts` | Records step timestamps/audio refs, saves `_timeline.json`, auto-generates transcript markdown |

### Execution flow

1. `tutorial.step()` / `tutorial.context()` **queue** actions and kick off TTS preloading in background
2. `tutorial.complete()` waits for all TTS preloads, then executes steps sequentially with overlays + cursor + voice
3. Timeline JSON is saved with a pre-built ffmpeg merge command
4. The **Playwright Reporter** (`src/reporter.ts`) runs `onTestEnd`, finds the timeline by `testTitle`, waits for the video file to stabilize, then executes the ffmpeg command

### Other modules

- `src/merge.ts` — Builds the ffmpeg filter-complex command (voice clips at precise timestamps + background music + video copy)
- `src/tts-provider.ts` — TTS provider abstraction: `CommandTTSProvider` (macOS say / custom `TUTORIAL_TTS_CMD`), `EdgeTTSProvider`, `TTSManager`
- `src/slugify.ts` — Unicode-aware slug generation (handles Latin diacritics + Arabic hamza marks)
- `src/transcript.ts` — Shared transcript markdown builder + parser + `applyCorrections()` (writes edited transcript texts back into the test source)
- `src/bin/export-transcript.ts` — `tutorial-transcript` CLI: regenerates transcript markdown from timeline JSON; `tutorial-transcript apply` writes edited transcripts back into the test sources

### Package exports

Entry points: `playwright-director` (main), `playwright-director/reporter`, `playwright-director/slugify`, `playwright-director/site` (types), `playwright-director/client` (headless embed data API, browser-safe), plus `playwright-director/styles.css` and `playwright-director/schemas/*`.

## Key design decisions

- **Docs surfaces for user-facing actions:** README (Key Features + Methods table + a section), `skills/tutorialize/references/api.md` (§3 table + a section + checklist), `references/storytelling.md` (when to use it), `SKILL.md` and `agent.md` (one line each), `landing/index.html` (feature card). Zoom and `typeBlurred` are the reference examples.

- **Voice cache** (`src/voice-dir.ts`): clips go to `voiceCacheDir()` = `TUTORIAL_VOICE_DIR` or `tutorials/.cache/voice` (outside the app's `static/`/`public/`, so they never ship in its build); recording, merge (`buildMergeCommand` default `audioDir`) and `regen-voices` all use it. Files are content-hashed (`md5(lang:text)`). The browser plays `<audioBaseUrl>/__playwright-director/voice/<file>`, answered from the cache by a `page.route` registered once per page (`TutorialVoice.ensureVoiceRoute()`). A clip missing from the cache but present in the pre-0.5 `static/audio/tutorial-voice/` is copied in on first use (`adoptLegacyClip()`), so upgrades re-synthesize nothing.
- **`testTitle`, `testFile`, `projectName`** must be passed to the constructor for the reporter to match timelines to test results. Without `testTitle`, the merge step silently skips.
- **`backgroundMusic` defaults to empty string** for external consumers. Pass `backgroundMusic: ''` explicitly if you have no music asset.
- **Voice playback errors are silent** (`audio.onerror = () => resolve()`) — a wrong `audioBaseUrl` produces no narration without any error.
- All overlay HTML is built as string templates in `overlay-html.ts` and injected via `page.evaluate()`.
- **Audio/video sync uses a recorded black marker, not wall-clock anchors.** Recording starts at page creation and Playwright may buffer several seconds before the video file exists, so no wall-clock anchor (constructor time, file `birthtime`) reliably maps to the tape's t=0 — on a real app the error reached ~5s (constant), leaving every frame lagging the audio clips. `complete()` flashes a full-screen black div for 500ms right before `timeline.start()`; the reporter finds it with `ffmpeg blackdetect` (`detectSyncMarker`) and rewrites the merge command's `-ss` with the marker's end — the exact video time of timeline zero. `videoTrimMs` (birthtime, else constructor anchor) stays in the timeline as the fallback when the marker isn't found; `syncMarker: true` in the timeline JSON tells the reporter to look for it.
- **`TUTORIAL_DEBUG_CLOCK=true`** burns a wall-clock overlay (epoch ms % 1e6, bottom-left) into the recording — comparing the clock shown in a frame at video time T against `timelineStartEpoch + T` measures desync frame by frame. Debug only: the clock ends up in the final video.
- **Narration/action overlap** (option B of `docs/narration-action-overlap.md`): a voiced step's action starts *during* the narration clip at `narrationActionOffset(duration, fullText, doText)` — character-share estimate of the do/explain boundary (`(len(do)+2)/len(full)`), 25% for single-phase, voiceText split at its first `'. '`. `TutorialVoice.startPlayback()` starts browser playback without awaiting the end; wall clock is clamped to `max(duration, offset + action)` so the next clip never overlaps in the ffmpeg mix. Non-voiced steps keep the serial `stepDelay → action` path. Timeline/merge/transcripts/cache are untouched.
- **Overlay position** is configurable via `overlayPosition: 'TL' | 'TR' | 'BL' | 'BR'` on `TutorialOptions` (default `'TR'`). Per-step override via `StepOptions.overlayPosition`. RTL mode (`lang: 'ar'`) mirrors positions automatically (TL↔TR, BL↔BR). CSS classes: `.tutorial-overlay-tr`, `.tutorial-overlay-bl`, `.tutorial-overlay-br` (TL is the base, no extra class).
- **Split mode** (`data-split` on the stage): when multiple scenes are active, the shared tab bar hides and each scene pane gets its own label header + a visible separator. `focus()` accepts `{ ratio: [30, 70] }` for asymmetric splits. In single mode the regular tab bar shows all tabs.
- **Narration corrections** (`tutorial-transcript apply`): the workflow is *edit the generated transcript markdown → apply → re-run*. `applyCorrections()` pairs transcript entries with timeline steps by kind (context/step/complete) + i18n key, consumed in file order (duplicate keys correct each occurrence in turn; keyless entries fall back to kind-order), then rewrites the original text in `testFile` as a quoted string literal (searching `'`/`"`/`` ` `` with escaping, forward-cursor so source order follows step order). Two-part narrations (`${do}. ${explain}`, `${title}. ${text}`) are split at the first `'. '` and both halves replaced. Guard rails: a first sentence equal to the step key (identity translate) is never rewritten — only the free half is edited; texts not found as literals (i18n catalog) are reported for manual fixing with their key. On success the timeline JSON's step texts are updated too, making a second `apply` a no-op. The transcript itself is regenerated by `buildTranscriptMarkdown()` (shared between `TutorialTimeline.save()` and the CLI).
- **Variants** (`variant` option, default `env TUTORIAL_VARIANT`): suffixes `testName` (`<name>-<variant>`) so all outputs (video, timeline, transcript, screenshots) coexist with the base recording; the variant is stored in the timeline JSON and stamped on `<html>` as `data-tutorial-variant`. The reporter matches timelines by `testTitle` AND variant, newest mtime as tiebreak. `mobileStage(scenes, device?)` (exported) returns `test.use()` options (viewport + video = N phone panes, from Playwright `devices`), inert unless `TUTORIAL_VARIANT=mobile`.
- **Mobile variant preset** (`variant === 'mobile'`, internal — no extra options): (1) *pinned split* when 2+ scenes — `data-layout="split"` on the stage, all scenes always visible at equal width, tab bar never shown, labels always visible (inactive dimmed), `focus()` ignores ratios and never sets inline flex; (2) *compact overlay* — pure CSS-variable remaps under `html[data-tutorial-variant='mobile']` from `--tutorial-*-mobile` values defined in `:root` (so consumers tune them with a plain `:root` override), plus icon/step-badge hidden via `--tutorial-icon-display-mobile`/`--tutorial-badge-display-mobile`. Outside the mobile variant, stage/focus behavior is strictly unchanged.
- **Overlay surface is variable-driven**: `--tutorial-overlay-bg` (was hardcoded `#fff` — set an `rgba()` for transparency), `--tutorial-overlay-blur`, `--tutorial-overlay-shadow`, `--tutorial-icon-size`, `--tutorial-context-max-width`.
- **Site variant filter**: the manifest entries carry `variant` (read from the timeline, filename suffix `-mobile`/`-tablet` as fallback); the gallery index shows a Desktop/Mobile filter when variants exist and cards get a variant badge.
- **Site step guide layout** is configurable via `tutorials.stepsLayout` in `tutorial-site.config.js`: `'text'` (default — text-only cards, click reveals the screenshot inline), `'cards'` (numbered text cards with a small screenshot, click opens a lightbox), `'full'` (narration text + full-width screenshot per step), `'none'` (no guide). The thumbnail strip is a separate toggle, `tutorials.showStrip` (default `true`), rendered above the guide; clicking a strip thumbnail opens the screenshot in the lightbox with its step's number, title and text as a caption. Scaffold passes both to the template through `site-config.json`.
- **Site step data**: `buildStepsDetail()` (`src/site/generate-manifest.ts`) merges timeline steps with the scanned screenshots by step number into `stepsDetail` on the manifest entry: leading context narrations become `description` (shown under the title), mid-flow contexts stay in the list as unnumbered callouts, and the `Complete` narration is excluded. Display numbers are sequential (contexts don't count). A video with no timeline still gets a screenshot-only guide, and screenshots whose step is absent from the timeline (older recordings) are inserted at their position with no text.
- **Demo site on GitHub Pages** (`.github/workflows/deploy-site.yml`): every push to `main` re-records the e2e suite in tutorial mode and publishes to the `gh-pages` branch — `landing/index.html` (self-contained static marketing page, no build step) at the site root, the generated gallery under `/gallery/`. Narration comes from the edge-tts fallback (`pipx install edge-tts`; unlike `test.yml`, no silent `TUTORIAL_TTS_CMD` is set, so the public videos have real voice). The committed `tutorial-site.config.js` sets `baseUrl` to the full URL including `/gallery/` — scaffold derives Astro `site` + `base` from it, which is what makes sub-path hosting work. `.gitignore` no longer ignores that config file.
- **In-app widget** (`templates/site/public/widget.js` + `src/site/embed.ts`): the built gallery serves `widget.js` at the site root and one payload per tutorial at `embed/<id>.json` (plus `embed/index.json` listing slugs), written by `scaffold()` via `buildEmbedFiles()`. A consuming app loads the script (base URL derived from `document.currentScript.src`) and marks elements `data-tutorial="<slug>"`; a delegated click listener opens a native modal `<dialog>` (`showModal()` inside the shadow root: page inert, Esc via the `close` event, backdrop click = click on the dialog element, focus restored to the trigger) with the video, description and chapters — an `<ol>` of buttons that seek the video (`aria-current="step"` from `timeupdate`, ↑/↓/Home/End roving focus), each screenshot behind its own 44px toggle. Numbers are precomputed in the payload (sequential, contexts don't count). `window.PlaywrightDirector.open(slug, {lang}) / close / load / strings` is the API. Language: `lang` option → trigger `data-tutorial-lang` → `<html lang>`; it selects the payload (client fallback) and the UI strings. The widget keeps its own fr/en/ar copy of the keys it uses (no build-time injection — simplest; `tests/strings.test.ts` runs widget.js in a `vm` and checks every text equals `src/site/strings.ts`). Theming is CSS custom properties only: `--pd-accent|surface|text|muted|border|radius|font|focus-ring` defaulted on `:host`; the payload `accent` goes in a second `:host` rule as `var(--playwright-director-accent, <accent>)` (old variable still honoured); page rules on `.playwright-director-widget` beat both. Fetching `client.js` / `embed/*.json` cross-origin needs CORS on the gallery host. `e2e/widget.spec.ts` serves widget + client + payloads via `page.route` (needs `npm run build`) and runs axe (`@axe-core/playwright`, devDependency only) on the open dialog in fr and ar.
- **`typeBlurred(locator, value, { delay?, blur?, reveal? })`** applies an inline `filter: blur()` to the field *before* the first keystroke and deliberately leaves it on (the finished value must never become readable); `reveal: true` or `unblur()` removes it. Tutorial mode only — plain runs just `fill()`.
- **Camera zoom** (`zoom(locator, { scale?, duration?, blur?, transition? })`, `src/zoom.ts`): zooms the *top-level page* with a CSS transform on `<html>` (so the whole stage, iframes included, zooms; `boundingBox()` gives main-frame coords for scene elements). Geometry is pure and unit-tested in Node (`zoomScale`, `zoomFrame`, `zoomFrames`): auto scale fits the target to 70% of the viewport capped at 2.5×, never < 1×; the target glides toward the viewport center while the origin is clamped so the scaled page always covers the viewport (no blank canvas). Frames are precomputed (~60fps, ease-in-out) and played by a `requestAnimationFrame` loop in-page; zoom-out plays them backwards. Three in-page details: (1) the tutorial UI (`#tutorial-overlay`, `#tutorial-cursor`, `#tutorial-email-preview`, `#tutorial-debug-clock`) is moved into `#tutorial-zoom-layer`, a `popover="manual"` shown in the **top layer** — top-layer content ignores the `<html>` transform, so banner and cursor stay crisp and unscaled; overlay/cursor injection appends into that layer while it exists, and finite CSS entrance animations are `finish()`ed after each move so the banner doesn't flash; (2) a transformed `<html>` becomes the containing block of `position: fixed` elements (the stage included), so they now scroll with the page, and the zoomed page overflows, so a Playwright action may scroll the top document mid-zoom (seen with `typeSlowly` inside a scene). Each frame therefore uses the *live* scroll: html offset = `base − (scrollX, scrollY)`, every viewport-fixed element gets an inline `translate` of the opposite offset, and a `scroll` listener re-applies the current frame — the picture stays put whatever scrolls. Everything is restored on zoom-out; (3) the blur is a `backdrop-filter` div in the layer whose evenodd `clip-path` hole tracks the target each frame. Robustness: the animation loop is driven by rAF with a 50ms `setTimeout` fallback (a stalled rAF can't hang the step); a loop stops as soon as its zoom is no longer `window.__tutorialZoom`; a zoom-in finding a leftover zoom restores it first; a failed zoom-out warns and calls `__tutorialZoom.restore()` without animation. The cursor is moved with the page each frame and its final position synced back to `TutorialCursor.setPosition()`. No-op outside tutorial mode; not recorded in the timeline.
- **Fast-forward** (`fastForward(speed, action, { vhs? })`, or `startFastForward(speed)` / `endFastForward()` markers, `src/fast-forward.ts`): spans recorded at real speed are re-timed by ffmpeg in the merge. The timeline stores each span as `{ startMs, endMs }` in *tape* time (what setpts reads after `-ss`) plus `outputStartMs/outputEndMs` and `speed`; everything else is stored in *final-video* time — `addStep` maps its timestamp through `fastForwardOutputMs()` (an open span counts as ending now), `totalDurationMs` is the final length (`tape − Σ L(1 − 1/S)`), `tapeDurationMs` is the recorded one. So voice `adelay`s, `-t`, music `atrim`, transcripts, the reporter's duration patch and the site need no special casing — only `buildMergeCommand` adds `[0:v]setpts='(T−Σ(clip(T,a,b)−a)(1−1/S))/TB',fps=25[,noise,rgbashift with enable=between(t,…) on vhs spans][vout]` and maps `[vout]` instead of `0:v`. One piecewise setpts, no split/concat. `startFastForward()` waits for the playing narration clip (`narrationEndsAt`, set after each `startPlayback`) so speech never overlaps sped-up video; `complete()` closes a span left open right after its step's action (one call site, before the step screenshot — so the VHS OSD never reaches screenshots and no later narration overlaps a span). Only valid while `complete()` runs (`recording` flag) — outside it warns and no-ops; speed must be `> 1` (throws in both modes). The in-page VHS OSD (`#tutorial-fast-forward`: `▶▶ ×N` badge, scanlines, tracking band whose animation is slowed by `speed`) is listed in the zoom layer's `UI_IDS`. Any number of spans per video, each with its own speed. The e2e `96-fast-forward.spec.ts` records ONE video with two waits (×4 via `fastForward()`, ×8 via explicit markers), and `global-teardown.ts` asserts the merged file's duration is within 0.5s of the predicted `totalDurationMs`.
- **Unvoiced steps are recorded in the timeline** with empty `audioFile` and `durationMs: 0` (steps with `skipVoice`, or any step/context/complete when voice is disabled), so their text reaches the site's step guide. Empty `audioFile` marks them: `buildMergeCommand`, `buildTranscriptMarkdown`, `applyCorrections`, and voice-prerender all skip such steps — transcripts stay narration-only and no TTS is synthesized for them.
- **Languages** (`TUTORIAL_LANG`, read in the constructor): overrides `options.lang` and suffixes `testName` `<name>[-<variant>].<lang>`; `tutorial.lang` exposes it so the spec drives the app UI. The reporter also matches the timeline `lang` when the env is set. The manifest derives `slug` (id minus `.<lang>` when it equals the timeline lang) and `langs` per slug; `buildEmbedFiles()` writes `embed/<slug>.<lang>.json` for each language and `embed/<slug>.json` = default (`config.lang` first entry) or first recorded; `index.json` lists one entry per slug + `defaultLang`. Gallery: one home page per language (`pages/index.astro` = default language, `pages/[lang]/index.astro` for the others; `TutorialsHome` filters by its `lang` prop, all videos when only one language exists, and links the language homes), video-page switcher (same slug + variant), prev/next within the page language, `<html lang dir>` per page (`Base.astro` `lang` prop; ar/he/fa/ur → rtl). Site chrome strings: `src/site/strings.ts` (en/fr/ar) merged with config `strings` by `scaffold()` into `site-config.json`, read by `templates/site/src/i18n.ts` `t(lang, key, vars)`. macOS Arabic voice is `Majed` (`Maged` renders near-silent on current macOS).
- **Headless client** (`src/client.ts` → `playwright-director/client`): browser-safe, no runtime imports (types only), so `dist/client.js` is copied verbatim by `scaffold()` to `<site>/client.js`. `widget.js` (a classic script) gets its data through `import(BASE + 'client.js')` — one implementation of fetch, lang fallback (`<slug>.<lang>.json` → `<slug>.json`), URL resolution and error messages. Embed payloads carry `schemaVersion: 1` (`EMBED_SCHEMA_VERSION`); `schemas/embed-v1.schema.json` is shipped and exported. Additions keep the version; breaking changes bump it.
- **Chapters**: `buildStepsDetail()` gives every timeline step `at` (startMs / 1000, final-video time — fast-forward already mapped) and `key`; a title equal to its key (identity translate) becomes the narration's first sentence. The manifest carries `durationSeconds`, timeline `lang` and the `<id>-poster.*` file (preferred poster). The video page renders a `.step-time` button per step that seeks `#tutorial-video` and marks the playing step `aria-current="step"`.
- **`_headers` + base path** (`buildHeadersFile()`, `src/site/scaffold.ts`): every build writes `public/_headers` (Cloudflare Pages / Netlify) — CORS (`config.cors`, default `'*'`, `false` = no file) + `Cache-Control` 300s on `embed/*`, `client.js`, `widget.js`, one week on `videos/*` (names are not hashed, so not immutable). Rules are prefixed with the base path. `baseUrl` may be a full URL (site + base) or a bare path (`/help/` → Astro `base` only); `build-site --base=<path>` overrides it. `-y` (or no TTY) never prompts for a missing config; `--only=<slug,...>` keeps scanned tutorials whose id is the slug or starts with `<slug>.` / `<slug>-` (`matchesOnly()`), i.e. all its languages and variants.
- **`build-site` resolves astro from the package, not the consumer** (`linkAstro()`, `src/site/build-site.ts`): astro is a dependency of playwright-director; the scaffold in `<output>/.astro-build` gets a `node_modules/astro` symlink to the copy resolved with `createRequire(import.meta.url)`, and the CLI runs as `node <astro bin> build`. Node/Vite follow the symlink to astro's real path, so its own deps resolve under any linker (bun isolated, pnpm, npm workspaces). `tests/workspace-build-site.test.ts` (opt-in, `PD_WORKSPACE_TEST=1`, needs `npm run build` + network) packs the package and builds the `tests/fixtures/workspace` monorepo with bun, pnpm and npm. Site config `timelines` / `videos` override `<input>/output` / `<input>/videos`.
- **Site themes** (`theme`, default `'academy'`; `build-site --theme`): `scaffold()` copies in this order — `templates/site` (shared pages, `src/components/*`, `styles/components.css`) → `templates/themes/<theme>` as `src/theme/` (`Layout`, `Home`, `VideoPage`, `theme.css`) → config `overrides` folder → generated data (`src/data/*`, so overrides can't clobber it). Shared pages import `../theme/*`; themes restyle shared components in `theme.css`, loaded after `components.css`. Unknown theme fails the build. `themeSwitcher` (label → URL) renders links between builds; the entry whose path equals the build base is `aria-current`.
- **Design tokens** (`src/site/tokens.ts`): `tokens` names map to `--pd-*` (`TOKENS`), written by `tokensCss()` into `styles/user.css` on `html:root` (beats the theme's `:root`), then config `css` appended; unknown names fail with the valid list. `primaryColor` / `font` = `tokens.primary` / `tokens.fontBody`. `googleFonts` overrides the theme's font list (`false` = none). `THEME_PRIMARY` is the widget accent when no primary is set — keep it in sync with each `theme.css` (Classic is `#4f46e5`: `#6366f1` failed AA on white).
- **Sections & config slugs**: `categories.<id>.items` orders videos (unlisted ones follow in scan order), `blurb`, `featured`, `premium`; empty sections are dropped. Config lookups (`items`, `premium`, `featured`, `links`) use `configSlugOf()` — the slug without `.<lang>` and `-<variant>`, so one entry covers every recording of a tutorial.
- **Role chips** (`tutorials.roles`, Académie hero): `{ id: { label, sections } }`, passed into the manifest; unknown section ids fail the build. A chip is an `aria-pressed` button ("All" first) calling `setFilter({ sections })` — one shared filter with search and variant; the table of contents hides the sections the filter hides. No roles = no chips (0.6.0 section chips duplicated the table of contents).
- **Links**: test option `links: { app, docs }` (stored in the timeline) merged under config `tutorials.links[slug]`, each resolved by `resolveLink()` on `appUrl` / `docsUrl` (`{lang}` → timeline lang; absolute URLs kept). Académie shows a call-to-action (`cta`, default on) when there is an app link.
- **SEO** (`src/site/seo.ts`, only with a full `baseUrl`): VideoObject JSON-LD with chapter `Clip`s computed in Node by `scaffold()` and stored in `tutorials.json` (templates can't import `src/`); `uploadDate` = oldest `recordedAt` of the slug. `Seo.astro` writes canonical, hreflang (+ `x-default`), og:*. Build writes `sitemap.xml` (hreflang alternates), `robots.txt` (host root only) and `links.json` (docs URL → tutorials).
- **Site i18n plurals**: `t()` tries `<key>_<Intl.PluralRules category>` (`sectionStats_one`, `_two`, `_few`… for ar) before `<key>`.
- **Quick-view dialog** (`VideoModal.astro`): opens only from `[data-quickview]` inside a `.video-card`; prev/next stay within the card's `.category`; ←/→ are swapped under `dir=rtl`. The box follows the video ratio (`--pd-video-ratio` set on `loadedmetadata`, `--pd-video-w`). RTL arrows: `‹ ›` are bidi-mirrored glyphs, so never flip them with `scaleX(-1)` (only `←` gets it); up/down chevrons use physical borders.
- **Site e2e** (`e2e/site.spec.ts`): builds both themes from a generated 12 s ffmpeg video (fr + ar), serves them with an in-test static server that answers Range requests (seeking needs `206`), and checks overflow at 375 / 1280, chapter seek + `?t=`, Académie search, and axe on home + video page per language. Configs are written as `.mjs` — Playwright's loader turns a `.js` outside a `"type": "module"` package into CommonJS (`default` ends up nested).

## Environment variables

| Variable | Controls |
|---|---|
| `TUTORIAL_MODE` | Master switch — must be `'true'` to generate video |
| `TUTORIAL_VARIANT` | Recording variant (suffixes outputs; `mobile` = compact overlay + pinned split) |
| `TUTORIAL_VOICE_DIR` | Voice clip cache (default `tutorials/.cache/voice`) |
| `TUTORIAL_LANG` | Recording language (overrides `lang`, suffixes outputs `.<lang>`) |
| `TUTORIAL_VOICE` | `'false'` disables TTS (default: enabled) |
